+### Agent model

+**Decision.** Single steerable agent + soft modes. One opt-in scout as a child `pi` process behind `bin/scout` (see Scout).

+### Compaction
+
+**Decision.** Mario defaults, `keepRecentTokens` trimmed 20k→16k. Plus `extensions/compact-cap.ts`: a flat ~210k ceiling (raised from 165k 2026-09-29). At `turn_end` over the cap it only warns, once per crossing, to `/handoff` and start a fresh session; at `agent_settled` it compacts, which aborts nothing. Session command `/compact-cap [on|off|<n>k]`, 30k floor (below compaction's own output it thrashes).

Until 2026-11-14 the cap compacted mid-run and prime-reminder auto-resumed the aborted run; that was retired because short sessions beat a run resumed on a summary, and compaction is where rules got lost. Cost: a run that crosses the cap keeps growing until it ends (20-50k overshoot was measured before).

+### Jobs
+
+**Decision.** `background.ts`: `bg_run`/`bg_status`/`bg_kill`, bash capped at 120 s default / 600 s max (scout and `timeout …` exempt), and a zero-token watchdog (`lib/watchdog.ts`, pure, tested). Foreground bash is pi's own tool with wrapped operations: no output, CPU or network for 90 s kills the process group (`killed: idle 90s …`); `ssh`/`docker`/`kubectl`/`scout`/`timeout` are exempt. `bg_run` jobs are never killed; a quiet idle job wakes pi at 5/15/45 min, a busy silent one at 30 min, at most 3 wakes. Declared signals win: `$PI_HEARTBEAT` (touch it) and `bg_run health` (checked every 30 s). Job messages are steered into a running turn (seen before its next model call) and start a turn only when pi is idle. Bash has four owners, one job each: `background.ts` caps the timeout (`tool_call`) and runs the command (re-registers pi's own bash definition with watched operations, pi's documented override pattern, so schema and renderer are unchanged); `pi-rtk-optimizer` rewrites the command text in its own `tool_call`, which runs after ours because local extensions load before packages, and the watchdog's exemptions still match the rewritten `rtk docker …` (`tests/watchdog.test.ts`); `pi-minimalist` draws the rows. Job tails (completion message, watchdog wake, `bg_status`) collapse `\r` progress redraws to the text a terminal would show, so a progress bar is one line, not thousands of chars (2026-10-28). Jobs do not outlive pi: `session_shutdown` aborts every running job's controller and clears the job table, so nothing started with `bg_run` survives the session that started it.
+
+**Why.** Every long-running path needs a limit or a health signal. Evidence first: exit, wake_on, declared signal, output, then CPU/network/process change; a failed `ps`/`nettop` never kills or wakes. `nettop` must run with `-n` (5.1 s per call without it). Spiked on 1.4.0: a 0.05 s CPU threshold killed a throttled download, so any increase counts.

+### Placement
+
+**Decision.** Put each job in the tool that owns it (git hook, CLI, script): one job per module, few links between modules, the simplest form that works. A harness extension needs a reason: the job lives inside the harness (stream, compaction, rendering, in-loop retry) or no tool can see it. No pi extension for git or file work a hook or script can do.

+### Scout git guard
+
+**Decision.** `bin/guard/git` is first on PATH in every scout child. It blocks push, pull, merge, rebase, reset, clean, stash, checkout, switch, restore, commit and add, only against the scout's own repo; exit 1 is a refused command, exit 77 means the guard is misconfigured (no real git) and nothing can run.

+**Why.** A token scan misses wrapper spellings; PATH catches every call of `git` by name. A tripwire, not a sandbox: an absolute `/usr/bin/git` or `git -c alias.x=...` gets past.

+## Scout
+
+**Cost visibility.** Scout sessions live under `~/.pi/agent/sessions/scout/<pid>/` because `pi-usage-widget` walks the sessions tree recursively (`data-collection.ts:456`) and nothing else: scout spend then lands in today/all-time with no widget change (verified: moving the scout files out shifted today by exactly their summed `usage.cost.total`). `/resume` reads only `sessions/<encoded-cwd>/` (`session-manager.js:550`), so the subdirectory never shows up there, and the widget's shared `timestamp:totalTokens` dedupe keeps `--fork` copies from double-counting the parent. Every usage package surveyed on 2026-09-16 (pi-usage-dashboard, @pify/usage, pi-usage-bar, pi-footer, pi-daily-cost, pi-token-usage, pi-tracker, pi-atlas) reads either in-process events or this same tree, so none needed replacing.
+
+**Visibility without tokens (`extensions/scout.ts`).** The wrapper stamps `sessions/scout/.running/<pid>.meta` (model, thinking, start, parent `PI_SESSION_FILE`, task) and writes its digest to `.running/<pid>.out`; an `EXIT` trap moves both to `.done/` with `rc` and `finished`. The extension polls once a second: `.running` drives a footer line (`⟳ scout claude-sonnet-5/low 0:42 $0.013`, cost summed from the child's own `<pid>/*.jsonl`), and `.done` files whose parent session matches become `pi.appendEntry("scout", …)` entries, which pi never sends to the model, rendered one line collapsed (model/effort · elapsed · cost · outcome · task) with the digest under ctrl+o. Ownership by session file means two pi terminals never claim each other's scouts; shell launches with no parent are discarded; a dead-pid `.running` file (SIGKILL skipped the trap) is moved to `.done` as rc 137 ("killed"), so its cost still reaches the parent. The registered-tool alternative (bundled `subagent` shape, `onUpdate` streaming, native parallel tool calls) was planned and rejected on 2026-09-16: 200 to 300 resident tokens and a dispatch re-probe for a cosmetic gain. Measured: headless parent exits normally (timer is `unref`'d) and persists the entry; interactive single and `& wait` pair each produce one entry per scout. `session_shutdown` runs one final claim because a headless parent usually exits within the poll interval of its scout finishing; before that sweep, 10 of 10 headless A/B sessions on 2026-09-16 lost their entry. The ten-minute orphan sweep now covers only SIGKILLed parents and scouts launched from a bare shell.
+
+**Scout tool budget.** `bin/scout.prompt.md` caps the child at 8 tool calls and asks for `grep -n` plus line-range reads. Before the cap, the same S1 auth-trace prompt cost one child 5 calls and 12k tokens and the next 10 calls and 97k; after it, four reps landed at 6 to 7 calls and 11k to 16k tokens with every sub-answer intact (`/Users/anshulj/Dev/pi-scout-vs-subagents-ab-2026-09-16.md`). Every correct child across 22 A/B runs finished within 7 calls, so 8 is a cap on wandering, not on coverage.
+
+Why each flag is there is recorded in `~/Dev/pi-scout-plan-2026-09-16.md` (18 gaps, each with the evidence). The ones that bit: `-e <dir>` silently loads nothing (use `index.ts`); `--no-extensions` drops the OAuth compatibility shim, which is loaded back explicitly when installed; `grep/find/ls` are opt-in builtins that only `-t` enables; Anthropic's OAuth pool rate-limits above two concurrent agents, so the delegation rule caps parallel at two.
+
+**Dispatch is the fragile half, and it is prose.** With the old rule ("dispatch before a third file read... a narrow grep: do it yourself") the parent dispatched 0/12 times on a genuine multi-file trace; every thinking trace said "dispatch is right, but I'll do a quick grep first" and momentum finished the job, pulling 25–42 KB into context. The clause was the on-ramp. The current rule in `persona-pi.md` ("decide before the first tool call; a scoping grep is the first read") went 4/4 with the scout as the first call and 6–17 KB into the parent, at +25–30 s latency. On the live config: explicit-cue trace 4/4, casual phrasing 4/4, familiar-repo multi-file trace 3/3, narrow lookup 0/3 and single-known-file edit 0/3 (no over-dispatch). A second erosion was then measured and closed: after the digest the parent re-read cited files whole (2/4 runs, 13–22 KB); "re-read a cited line range only when you need the exact text, never the whole file" took that to 0/4 and 3–16 KB. Explicit "use the scout" dispatch was 4/4 under both rules. Re-run this probe (`/tmp/spike/run6.sh` shape: headless parent, `-nc --append-system-prompt <AGENTS variant>`, unfamiliar-package trace prompt) whenever the Delegation fragment changes.
+
+**Worker mode, retired 2026-11-14.** `--rw` (2026-09-30) ran a scout as an editing worker under `extensions/worker-sensors.ts` (files-allowed, bash blocks, settle checks, `verdict.json`). It was retired with auto runs: agentic loops and subagent implementation did not pay off in practice, and implementation now happens in short main-session slices. What survived: `bin/guard/git` (now read-only rules) and the settle checks' idea, as `bin/slice-check.ts`. The history is in git before this date.

+The bundled `examples/extensions/subagent` was measured as the alternative (687 resident tokens, typed single/parallel/chain) and rejected: it returns the child's whole streamed transcript as the tool result, 72–79 KB per dispatch against the wrapper's 3–4 KB, and its child inherits the full ~25k prompt.

+/**
+ * Pure logic for bin/slice-check.ts: read a card, and judge a slice's diff against it.
+ * No I/O here; the CLI gathers file contents and command results and passes them in.
+ */
+import { isAbsolute, matchesGlob, normalize } from "node:path";
+
+/** The two card fields slice-check enforces. The other fields (outcome, interface, mechanism, out) are for people. */
+export interface Card {
+	doneWhen: string[];
+	files: string[];
+}
+
+function unquote(value: string): string {
+	return value.trim().replace(/^(['"])(.*)\1$/, "$2");
+}
+
+/**
+ * Split a flow list body on commas outside quotes and `{a,b}` brace groups, so a glob like `src/{a,b}.ts` and a
+ * quoted command like `"jq '.a, .b' x"` stay whole.
+ */
+function splitFlowList(body: string): string[] {
+	const items: string[] = [];
+	let depth = 0;
+	let quote: string | undefined;
+	let current = "";
+	for (const char of body) {
+		if (quote) {
+			if (char === quote) quote = undefined;
+		} else if (char === '"' || char === "'") {
+			quote = char;
+		} else if (char === "{") {
+			depth += 1;
+		} else if (char === "}") {
+			depth = Math.max(0, depth - 1);
+		}
+		if (char === "," && depth === 0 && !quote) {
+			items.push(current);
+			current = "";
+		} else {
+			current += char;
+		}
+	}
+	items.push(current);
+	return items.map(unquote).filter(Boolean);
+}
+
+/**
+ * Parse a card: `key: value` lines, with lists either as a flow list (`[a, b]`) or as `- item` lines under an
+ * empty `key:`. A fenced block around it is fine; unknown keys are ignored. Returns an error string, not a throw,
+ * so the CLI can print it and exit 2.
+ */
+export function parseCard(text: string): Card | string {
+	const fields = new Map<string, string | string[]>();
+	let listKey: string | undefined;
+	for (const line of text.replace(/\r\n/g, "\n").split("\n")) {
+		const item = /^\s*-\s+(.*)$/.exec(line);
+		if (item && listKey) {
+			(fields.get(listKey) as string[]).push(unquote(item[1]));
+			continue;
+		}
+		const pair = /^([\w-]+):\s*(.*)$/.exec(line);
+		if (!pair) continue;
+		const [, key, raw] = pair;
+		listKey = undefined;
+		if (raw === "") {
+			fields.set(key, []);
+			listKey = key;
+		} else if (raw.startsWith("[") && raw.endsWith("]")) {
+			fields.set(key, splitFlowList(raw.slice(1, -1)));
+		} else {
+			fields.set(key, [unquote(raw)]);
+		}
+	}
+	const doneWhen = fields.get("done-when");
+	if (!Array.isArray(doneWhen) || doneWhen.length === 0) return "card needs done-when: one or more shell commands";
+	if (doneWhen.length > 5) return `card has ${doneWhen.length} done-when checks; keep it to 5 or split the slice`;
+	const files = fields.get("files");
+	if (!Array.isArray(files) || files.length === 0) return "card needs files: the globs this slice may change";
+	return { doneWhen, files };
+}
+
+/** True when a repo-relative path matches one of the globs. `**` does not match dotfiles (node:path matchesGlob). */
+export function isAllowed(repoRelativePath: string, globs: readonly string[]): boolean {
+	if (!repoRelativePath || isAbsolute(repoRelativePath)) return false;
+	const path = normalize(repoRelativePath);
+	if (path.startsWith("..")) return false;
+	return globs.some((glob) => path === normalize(glob) || matchesGlob(path, glob));
+}

+const TEST_FILE = /(\.(test|spec)\.[cm]?[jt]sx?$)|(^|\/)__tests__\/|(^|\/)test_[^/]*\.py$|_test\.py$/;
+const TEST_CASE = /\b(it|test|describe)(\.(skip|only|todo|each))?\s*\(|\bassert\b|\bexpect\s*\(|\bdef test_/g;
+const TEST_SKIP =
+	/\.(skip|only|todo)\s*\(|\b(xit|xdescribe|xtest|fit|fdescribe)\s*\(|\b(skip|only|todo)\s*:\s*true|\bpytest\.mark\.(skip|skipif|xfail)\b|\bpytest\.skip\s*\(/g;
+
+export function isTestFile(path: string): boolean {
+	return TEST_FILE.test(path);
+}
+
+function occurrences(text: string | undefined, pattern: RegExp): number {
+	return text === undefined ? 0 : (text.match(pattern) ?? []).length;
+}
+
+/**
+ * Why a test file's change looks like the tests were weakened rather than the code fixed: fewer cases or
+ * assertions than before, or new skip/only markers. `undefined` content means the file does not exist.
+ */
+export function testWeakening(before: string | undefined, after: string | undefined): string | undefined {
+	const casesBefore = occurrences(before, TEST_CASE);
+	const casesAfter = occurrences(after, TEST_CASE);
+	if (casesAfter < casesBefore) return `test cases or assertions dropped from ${casesBefore} to ${casesAfter}`;
+	if (occurrences(after, TEST_SKIP) > occurrences(before, TEST_SKIP)) return "new skip/only/todo markers";
+	return undefined;
+}
+
+export interface CheckRun {
+	command: string;
+	exitCode: number | null;
+	timedOut: boolean;
+}
+
+export interface TestFileChange {
+	path: string;
+	before: string | undefined;
+	after: string | undefined;
+}
+
+/** Every reason the slice is not done; empty means it is. `card` undefined skips the card checks (--staged). */
+export function sliceFailures(input: {
+	card: Card | undefined;
+	runs: readonly CheckRun[];
+	changed: readonly string[];
+	testChanges: readonly TestFileChange[];
+}): string[] {
+	const reasons: string[] = [];
+	for (const run of input.runs) {
+		if (run.exitCode === 0 && !run.timedOut) continue;
+		reasons.push(`done-when \`${run.command}\` ${run.timedOut ? "timed out" : `exited ${String(run.exitCode)}`}`);
+	}
+	const card = input.card;
+	if (card) {
+		const outside = input.changed.filter((f) => !isAllowed(f, card.files));
+		if (outside.length) reasons.push(`changed outside the card's files: ${outside.join(", ")}`);
+	}
+	for (const change of input.testChanges) {
+		const why = testWeakening(change.before, change.after);
+		if (why) reasons.push(`${change.path}: ${why}`);
+	}
+	return reasons;
+}
